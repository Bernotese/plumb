- D-305 · 2026-11-13 · proposed (pl-backend, T-116; review F1, F2, F4 of T-111). Firewall files and units: the boot file is `/etc/plumb-agent/firewall.nft` (an agent path, so no Block can write it; F2), not `/etc/plumb/firewall.nft`. Its first lines hold the applied attributes (normalized JSON) and the listing that `nft list table inet plumb` printed at the commit (base64); then the script (`table inet plumb` / `delete table inet plumb` / the new table, one transaction). `plumb-firewall.service` (oneshot, `DefaultDependencies=no`, `After=local-fs.target nftables.service`, `Before=network-pre.target`, `ConditionPathExists=` the boot file, `WantedBy=sysinit.target`) loads it at boot (F4). Before the live change the agent arms a transient timer `plumb-firewall-rollback` (`systemd-run --on-active=120`, `nft -f` the boot file) and stops it at the commit or its own restore (F1). Every unit name that starts with `plumb-firewall` is an agent unit (`wire.IsAgentUnit`). A first apply writes a boot file that only deletes the table, so the restore, the timer and the boot always have a file; `state: absent` removes the boot file and disables the unit at the commit. `firewall` is `NotInImage` (seal removes `/etc/plumb-agent`) · one file is atomic for attributes, listing and rules; the timer works when the agent dies and stays down, without a new file

- D-307 · 2026-11-13 · proposed (pl-backend, T-116; review F3 of T-111). Safe apply details: one confirm try is 15 s on a new TCP and TLS connection (no keep-alive; idle connections closed first), 2 s between tries until the 90 s pass; 401 or another 4xx (409) ends the window at once with the restore.
