- D-191 · 2026-11-11 · Plumb never leaves a pending value. Revert of a pending-only change removes the pending value (write of the desired value; `revert=<key>` if the host check needs it): the running guest does not change, so the risk is `reversible` and there is no restart. Accept takes the pending value as the desired value, as for every drift. After every `Update` the Run observes again; if a managed value is still pending on a running guest, the Run does a cold restart (D-078), and the step fails if the value is pending after that. The Plan shows this restart as a `restart` change (risk `disruptive`) on `guest:config` for a change of `cores` or `memory` on a running guest; a Run without a planned restart fails instead of restarting. A stopped guest is not started. A pending cloud-init input is shown but not reverted by Plumb (D-185 A).
