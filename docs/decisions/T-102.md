- D-284 · 2026-11-13 · proposed (pl-backend, T-102; found in T-100 F1). Refines D-258 for a lost update result: the update step waits for the result and the hellos at once. A hello with the sent sha passes it. A hello with `reverted` (to the sent sha) fails it only once the link shows that the agent took the command (`Agents.Taken`); a revert before that is from an earlier update. A revert equal in all fields to the one the agent reported before the step is ignored too (review B1 of #202: a reconnect after a lost poll answer resends it while the link counts the command as taken). A hello with the old sha and no revert before a result is a reconnect of the old agent; its result follows. When the agent took the command and then polls no more (offline, `wire.OnlineSeconds`) for another `UpdateHelloWait` with no result and no hello, the step fails. A command that waits untaken keeps the `ApplyTimeout` limit · the agent exits 60 s after the swap also without a delivered result, so the result can be lost while the outcome is still known from the hellos; the agent drops an older revert marker when it starts the command and sends its reports in order, so "taken" separates this update's revert from an old one; the 15 min wait of T-100 told the person nothing for 15 min and ended in a wrong reason
