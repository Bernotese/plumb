- D-177 · 2026-11-11 · Key volume of the controller LXC: `pct create` adds `--mp0 <disk storage>:1,mp=/var/lib/plumb/key,backup=0` (a new 1 GB volume, not a host path). The installer checks that `/var/lib/plumb/key` is a mount point and gives it to user `plumb`, mode 0700; it never creates the directory itself. An existing Plumb LXC without this volume, or with the volume in the backups, is refused before any change (no hot-add; `--remove` and install again). `--remove` destroys it with the LXC and frees it with `pvesm free` if `pct destroy` left it. This replaces "no mount point" of D-083 · D-086 and D-102: the master key must exist and must never be in a backup of the LXC
- D-178 · 2026-11-11 · `plumb key init` in the installer: when `master.key` is missing, the installer runs `lxc-attach -n <id> --clear-env -- /usr/sbin/runuser -u plumb -- /usr/local/bin/plumb key init --data /var/lib/plumb` after `systemctl enable` and before the first start of `plumb.service`, with the installer's own stdin/stdout (never `pct exec`, never captured). It needs stdin and stdout on a terminal and checks this before any change; `--yes` does not skip it; `--dry-run` only prints the step. A failed key init stops the install before the start. A repair run with a key skips it and needs no terminal. So the real install is run by a person on a terminal (`ssh -t`), not by an agent, whose output is a log · D-086: the recovery key is shown once, on a terminal, and never reaches a log, file or agent context
