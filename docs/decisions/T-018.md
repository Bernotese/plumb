- D-055 · 2026-11-10 · Agent loop: `agent.json` holds `url`, `ca` (PEM), optional `token_file`, `state_dir`, `full_check`; the agent trusts only the pinned CA (no system roots, no proxy). Only a 401 drops the credential and enrolls again from the token source; every other failure retries with backoff (1 s to 60 s, jitter) and keeps the credential; 429 and 503 also keep the link (no new hello) and the agent waits at least their `Retry-After`. A command result is sent again until the controller accepts it; after a 401 it is dropped. A drift report holds only what changed since the last report: a new or changed drift (`differs`) or drift that went away (`unchanged`, so the controller can resolve the issue as `gone`); after every reconnect the agent sends hello and all open drift again. An `apply` merges its resources into the stored desired list and holds a lock that drift checks also take, so a check never sees a half-applied resource; after it the agent checks them again, so its own changes are never drift. A refused or failed resource stays in the desired list and is then reported as drift. A service whose `restart_on` resource is later in its own Block, or a cycle across Blocks, fails the apply before anything runs · no lost drift after an outage; no re-enroll storm when the controller is busy; restart order is always satisfiable
