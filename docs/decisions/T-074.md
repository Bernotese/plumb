- D-219 · 2026-11-11 · proposed (pl-frontend, T-074; default from the user's answer 7, D-218). One disk gate in the engine for guest creates and image builds: before a clone, `(used + reserved + disk) × 100 > limit × total` (integer bytes, no rounding; `driver.OverLimit`) refuses, and so does known thin-pool metadata use over the limit; unknown metadata use is no refusal. Check and reservation run under one mutex; a create holds its whole disk from before the enrollment token until `Create` returns, a build until it ends. A storage use that cannot be read refuses too. A Plan with creates gets a warning with the storage and the numbers when their disks together fail the check at propose time; the Run checks again. The limit is one setting, `PLUMB_DISK_LIMIT_PERCENT`, a whole number 50 … 95, default 85 · a full thin pool gives I/O errors in every guest (host B4) and a full clone can fill its whole disk; one gate makes parallel creates and builds count together; 95 leaves no margin, below 50 wastes the pool
