- D-308 · 2026-11-13 · proposed (pl-reviewer, T-115; refines D-299). Run order on one Target: the config writes of `guest:config` (cores, memory, bridge, tags) first, also on a stopped guest; then the start (`power: running`); then the disk grow (driver resize inside the disk gate of D-219; for a VM the agent command `grow` after the hello of the started or running agent); then the agent steps; then the stop (`power: stopped`). The `guest:config` step stays `running` until the root grow or the stop ends it. A failed agent step cancels the stop: the step fails with "not stopped: …" and the guest keeps running. A guest that the Run stops never restarts for a waiting value (the restart rule of D-194 sees it as stopped). Planning: a stopped guest with `power: running` has its resources planned unverified, as for a new guest (its agent cannot observe now); a stopped guest with `power: stopped` is not observed, and the Run marks its agent steps `skipped` with "Target stopped" without failing · D-299 said "start, then the other changes": a write after the start would make cores or memory of a VM wait for a restart that the Plan does not show
- D-309 · 2026-11-13 · proposed (pl-reviewer, T-115). Drift of `power` and `tags`: the guest poll compares the config digest and the power state (the binding stores "<digest> <power>"), so a start or stop outside Plumb of a managed `power` opens a `guest:config` Issue (revert starts or stops; a stop needs `allow_restart`); a planned stop stores the new key, so it is no drift. Bindings of an older controller are compared once after the upgrade. Tags are compared without case and order (lower case, sorted, duplicates dropped, as the Proxmox default tag style), written as one `;` list, and an empty set deletes the option. A 403 of a config write with tags says that the datacenter option user-tag-access or a registered tag refused it; Plumb gets no new right (D-081) · the Proxmox digest does not change with the power state
