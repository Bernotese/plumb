- D-212 · 2026-11-11 · PROPOSED (T-067 plan, waits for the user). Wire: `wire.Hello` gets `addrs` (a new agent always sends it, also empty; a missing field means "no address report"), and there is a new report type `addrs` for a changed list. It is not a second Hello, because the Run logic counts Hellos to see a restarted agent. Bounds: at most 16 addresses, canonical text of `netip.Addr`, no zone, no prefix, no IPv4-mapped IPv6, no duplicate, no loopback, link-local, multicast or unspecified address, sorted. A bad list in a Hello is stored as unknown and the Hello is taken; a bad `addrs` report gets 400. `link` takes one `addrs` report per agent in 10 s and writes only a changed list · agent reports are untrusted input (§7); display data must never cut the link to a guest
- D-213 · 2026-11-11 · PROPOSED. The agent reads its addresses with one netlink dump (standard library, no new dependency) at start and at every poll round, and sends an `addrs` report when the list changed, at most one in 30 s. No netlink subscription. It reports addresses of interfaces that are up and not under `/sys/devices/virtual/net` (all up interfaces when there is none, as in a container; T-038 makes the LXC rule final). It never reports loopback, link-local, multicast, IPv6 temporary, tentative, deprecated or DAD-failed addresses · a poll round is at most 30 s, so a subscription saves seconds and costs a socket, a goroutine and a debounce; temporary addresses change daily and are a privacy feature; Docker and VPN addresses are not the addresses of the guest in the LAN

- D-215 · 2026-11-11 · PROPOSED. Issue rule: resource `guest:address` (not `guest:config`).
