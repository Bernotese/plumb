The condition: a resource type writes every attribute to the guest in the same form as the desired list holds it, so the list gives root on the guest nothing that the guest does not hold already. All resource types of today meet the condition (`user` has no password attribute). A new type or attribute whose guest state is a derived form of a secret (password hash, database user, entry in a key store) must not put the clear value into the stored list. First choice: the attribute takes the derived form (for example `password_hash`, and the secret holds the hash). A type that must get the clear value needs its own decision before it merges; the direction is: the agent does not store this attribute and keeps the state that it observed after its own apply as the reference for the drift check, while `observe` and `apply` bodies still carry the value for the exact compare. No keyed hash and no question to the controller on drift. The agent never logs or sends the list. A `watch` replaces the list, so a resource that is no longer desired leaves the file; `seal` deletes it (D-098).
