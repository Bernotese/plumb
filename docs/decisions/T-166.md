An observed attribute whose reported value is a status text and not the guest's value is opaque (`resource.Type.Opaque`: `firewall.table`, `network.file`, `apt_repository.sources`, `sysctl.file`). A drift report with an opaque change stores one keyed hash for the whole resource type (the text `\0plumb-opaque\0<type>`), with the retention of every guest-value row (kept while its Issue is open, then 30 days after the last report; ignore once and rules do not end it). While it counts, a Plan that adds a value to any non-key attribute of a resource of that type, on any Target, is human-only (`accept-guest-data`), and `guest_data_matches` names each new element of the Plan (never the guest's text). Removals stay free. Every resource type is either a value type or names its opaque attributes; a test fails for an unclassified type · the agent cannot always map a hand change (any nft rule, any netplan or sources text) to the attribute model, and an old agent reports only the status text: the server-side rule fails closed for both, needs no agent change and no version gate; the price is that, after a hand change, token Plans that add values of that type need a person for 30 days
