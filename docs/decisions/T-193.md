- D-391 · 2026-11-14 · accepted (pl-architect, T-193; refines D-386). For an adopted Target (`spec.adopted`) the create-only attributes (`image`, `ip`, `gateway`, `user`, `ssh_keys`) and the container `features` are not compared at all (`GuestSpec.Adopted`, `driver.DiffGuest`); `kind` and the mutable settings (cores, memory, disk, bridge, tags, power) are. So Plumb never plans or writes them, and a later hand change of them is no drift · D-386 said "a missing create-only field is not compared", but the schema fills `ip: dhcp` and `user: plumb` as defaults, so "missing" cannot be told from a default; Plumb never set these values and can never change them, and writing `features` would change a container that a person made
- D-392 · 2026-11-14 · accepted (pl-architect, T-193; pl-lead's rule for item 2). The name of an adopted Target must equal the Proxmox name of the guest (VM `name`, LXC `hostname`); else 409 `guest-changed`. The driver accepts an adopted VMID (also outside the Plumb VMID range) only when the engine passed it as the guest of a bound adopted Target (`Adopter.SetAdopted`, the whole set each time) and, at every call, only while the guest is a member of the pool and still has the Target's name; a renamed guest, a VMID that another guest took, or a guest outside the pool is refused (`ErrForeignGuest` / `ErrNotFound`) before any write. `POST /targets/{name}/reenroll` is refused for an adopted Target (409 `adopted-target`): it would write `smbios1` or the LXC `env` of a guest that a person made; the install command (D-387) or the repair is the way in · the name is the identity of a guest on a reused VMID (D-320), and it keeps the restored-mode foreign check (D-322) working without a new rule
