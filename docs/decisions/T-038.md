# T-038 decisions (PROPOSED, pl-architect, 2026-11-12; not accepted until the user approves the plan)

- D-224 · 2026-11-12 · proposed (pl-architect, T-038). The base template of an LXC Image is pinned by URL + SHA-256 in the Image document, as for VM Images (D-077). Plumb does not read the Proxmox appliance index; the docs and the UI help list today's values. This refines "checksum of the appliance index" of D-097 · the pin is in the revision and needs no OpenPGP code; the index has only SHA-512 and its trust comes from a GPG signature
- D-225 · 2026-11-12 · proposed (pl-architect, T-038). New dependency `github.com/klauspost/compress/zstd`, the decoder only, to read `.tar.zst` base templates; the output is `.tar.gz` with the standard library · Proxmox system templates are zstd; Go has no zstd in the standard library; pure Go, widely used, no encoder needed
- D-226 · 2026-11-12 · proposed (pl-architect, T-038). An LXC Target has no bootstrap user: `user` is refused, `ssh_keys` go to `root` with the create parameter `ssh-public-keys` and are create-only; a named user comes from a Block · Proxmox has no cloud-init for containers; one path for users (Blocks)
- D-227 · 2026-11-12 · proposed (pl-architect, T-038). Plumb makes only unprivileged containers with `features=nesting=1` and no other feature, no `lxc.*` key, no mount point, no device. Observe refuses to manage a privileged container · least privilege for root in the guest; systemd in Debian 13 needs nesting
- D-228 · 2026-11-12 · proposed (pl-architect, T-038). The `symlink` resource has no fallback when `renameat2` flags are not supported (`EINVAL`, e.g. ZFS before 2.2): it fails with a text that names the directory, the flags and ZFS ≥ 2.2 · a plain `rename` loses the race protection of D-163
- D-229 · 2026-11-12 · proposed (pl-architect, T-038). The image storage `plumb-images` holds content `import,vztmpl`; the installer sets it on install and on a repair run; the start check of D-183 accepts `import` alone with a warning · no new storage and no new role; `Datastore.AllocateTemplate` covers the upload
- D-230 · 2026-11-12 · proposed (pl-architect, T-038). Repack: the base entries are copied byte-exact up to the end of the last entry; the agent, unit, wants link, CA and `agent.json` are appended as USTAR entries (uid 0, fixed mtime); the base is refused when it has a Plumb path, a non-directory parent of one, or exceeds 2 GiB / 200 000 entries. Name `plumb-ct-<image>-<d12>.tar.gz` from base checksum, agent checksum, CA, URL and format version; upload with the SHA-256 checksum parameter · no header round trip loses xattrs or special entries; same inputs give the same file
- D-231 · 2026-11-12 · proposed (pl-architect, T-038). The enrollment token of a container is `env` `PLUMB_ENROLL_TOKEN` at create (and at re-enrollment); the agent reads it from `/proc/1/environ` (`token_env` in `agent.json`); the Run step `guest:bootstrap` removes `env` after the hello · D-025 made concrete; the token leaves the config as soon as it is used
