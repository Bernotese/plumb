- D-312 · 2026-11-13 · proposed (pl-reviewer, T-114; D-289 made concrete). The host copy reads from the LXC with `pct exec <id> -- dd if=<path> iflag=nofollow`, piped through `head -c <limit+1>`, not with `pct pull`: the pointer at most 4 KiB, the backup at most the pointer size (≤ `--backup-max-size`), and never through a link (a link from user `plumb` to `/etc/plumb/plumb.env` would copy the token secret in clear). A copy must start with the magic `PLUMBBK\0` and match the pointer size and SHA-256; the host builds the name of the copy from the checked parts of the pointer name and writes it by temp file + rename (`mv -n`) in `<storage path>/plumb-backups` (0700, files 0600). A copy is never replaced: a name that exists with other content fails the run; a pointer time more than 1 day ahead of the host clock fails; the retention keeps the newest N by the time the host made each copy, never by the name (review M1 of #221). `iflag=nofollow` covers only the last part of the path (`/var/lib/plumb/backups` belongs to `plumb`); the strict name, `protected_hardlinks` and the magic check together keep a root file of the LXC off the storage, so the magic check is not redundant (review L1). `plumb-backup-copy` is generated by `install.sh` (one file for the user), reads `/etc/plumb/backup-copy.conf` (root 0600), and writes `status.json` into the root-owned `/var/lib/plumb-copy` of the LXC also on a failure. A repair run whose stored copy storage fails its checks only warns and keeps the timer; `--backup-storage none` removes it; `--remove` removes it, the copies stay. serve gets `PLUMB_INSTALL_ID`, `PLUMB_BACKUP_TIME` and `PLUMB_BACKUP_KEEP` in `plumb.env` (not as flags, so an older binary ignores them) · `pct pull` follows links as root and has no size limit; the magic check keeps a file that is not encrypted off the storage
