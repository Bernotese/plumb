- D-162 · 2026-11-10 · Resource `symlink` (key `path`; attributes `target`, `state`; `target` is required when present, 1 to 4095 bytes, no NUL, absolute or relative). The link path follows D-054: the parent is walked one component at a time without following links, no parent is created, a missing parent is observed as absent. The target is data: the resource uses only `fstatat(AT_SYMLINK_NOFOLLOW)`, `readlinkat`, `symlinkat` (temp name, then `renameat` over the path) and `unlinkat`; it never opens, stats, writes or chowns through the link. A link has no owner or mode attribute · `file` and `directory` refuse every symlink, so a Block needs its own type for links such as `sites-enabled`; following the target would let the link content point the root agent at any file
- D-163 · 2026-11-10 · `symlink` risk and drift: create and a new target are `reversible`, delete is `destructive`. A node on the path that is not a symlink is observed as `kind` (`file`, `directory`, `other`) and planned as the change `kind` → `symlink` plus `target`, both `destructive`. Apply replaces a regular file only when the plan holds that `kind` change (a stale plan is refused), and it never replaces or removes a directory or other node; `state: absent` removes only a symlink · the Plan shows possible data loss before approval; no silent loss of a file a person put there
