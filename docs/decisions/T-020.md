- D-162 · 2026-11-10 · Resource `symlink` (key `path`; attributes `target`, `state`; `target` is required when present, 1 to 4095 bytes, no NUL, absolute or relative). The link path follows D-054: the parent is walked one component at a time without following links, no parent is created, a missing parent is observed as absent. The target is data: the resource uses only `fstatat(AT_SYMLINK_NOFOLLOW)`, `readlinkat`, `symlinkat` (temp name, then `renameat2` over the path) and `unlinkat`; it never opens, stats, writes or chowns through the link. A link has no owner or mode attribute · `file` and `directory` refuse every symlink, so a Block needs its own type for links such as `sites-enabled`; following the target would let the link content point the root agent at any file
- D-163 · 2026-11-10 · `symlink` risk and drift: create and a new target are `reversible`, delete is `destructive`. A node on the path that is not a symlink is observed as `kind` (`file`, `directory`, `other`). With `state: present` it is planned as the change `kind` → `symlink` plus `target`, both `destructive`; Apply replaces a regular file only when the plan holds that `kind` change (a stale plan is refused) and never replaces a directory or other node. With `state: absent` such a node means the link is absent: no change, and Apply removes only a symlink. Leaf races: over nothing the link is renamed in with `RENAME_NOREPLACE`; over a link or a planned file with `RENAME_EXCHANGE`, and the old node must have the checked kind, else it is exchanged back; a remove first renames the link to the temp name and removes it only if it is still a symlink, else it renames it back. The temp name is fixed per link (`.plumb-link-<hash>`), so the next Apply removes a temp link that a crash left. Accepted limit: a writer of the parent directory who swaps the node twice within one Apply can block the undo; the swapped-in node is then kept under the temp name and Apply fails and names it · the Plan shows possible data loss before approval; a delete that can never succeed would reopen the same Issue after every Run; no node that the plan did not show is removed, and only a user who can already write that directory can win the race
