- D-437 · 2026-11-16 · proposed (pl-backend, T-238; pl-lead: yes; refines D-423, D-436). A container data disk (`mpN`) is written only to a **stopped** container. On a running container the Run stops it (the Plan needs `allow_restart`, so the add is `disruptive` there), writes `mpN` cold, and starts it. If that start fails (for example a symlink in the path, which Proxmox refuses), the Run detaches `mpN`, frees the volume by its read-back id with the token, starts the container again, and the step fails with a clear text. Only when that free fails does the Issue `guest:volume-left` open; while it is open, every Plan that adds a disk to that Target is refused (M1 of #365). No agent path check and no new agent command. A VM `scsiN` hot-add stays live and `reversible` · a refused hot-add of a mount point leaks a volume that the token cannot free (T-244 D13), while a cold write never leaks and a failed start can be rolled back with the token
