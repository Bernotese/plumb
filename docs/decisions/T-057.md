- D-211 · 2026-11-11 · A Target delete revokes its agent. The delete step deletes the guest first; only when that worked (or the guest was already gone) it calls `link.Revoke`, then deletes the binding. `link.Revoke(ctx, target)` removes the agent row and the enrollment token of the target in one transaction (`store.RevokeAgent`), marks the in-memory agent id revoked, drops queued commands and the sent sensitive lists, and ends an open poll with 401. The old credential then gets 401 on every link route, also after a restart and when a Target with the same name comes back (its new agent has a new id). A failed delete keeps the agent. After a crash, `Recover` finishes a delete step of the cut-off Run: when the guest of a deleted target is gone (driver `ErrNotFound`) and its binding is still there, it revokes the agent and deletes the binding; a guest that still exists (or cannot be checked) keeps both. The engine drops a drift or hello report of a target without a guest binding: no Issue, no event, no watch list.
