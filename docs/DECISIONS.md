# Decisions (one line each: ID · date · decision · why)

Later entries win over earlier ones and over `docs/BRIEF.md`. Add new decisions at the end (next: D-050).

- D-001 · 2026-11-10 · Scope is a homelab with one Proxmox host; no other hypervisors or clouds · user brief §4.1
- D-002 · 2026-11-10 · Guest OS is Debian stable and current Ubuntu LTS only · user brief §4.2
- D-003 · 2026-11-10 · Targets are VMs and LXCs, both first-class · user brief §4.3
- D-004 · 2026-11-10 · Built from scratch: no Terraform, OpenTofu, Ansible or Packer; Plumb talks to the Proxmox API directly · user brief §4.4
- D-005 · 2026-11-10 · One small driver interface hides Proxmox access and guest configuration; no other speculative abstractions · user brief §4.5
- D-006 · 2026-11-10 · Controller runs in an unprivileged LXC on the Proxmox host with a restricted API token, never root credentials · user brief §4.6
- D-007 · 2026-11-10 · Installation is one shell script / tarball on an empty Proxmox host; all later changes go through Plumb · user brief §4.7
- D-008 · 2026-11-10 · State is declarative and versioned; every change creates a revision with diff, history and rollback · user brief §4.8
- D-009 · 2026-11-10 · Web UI is the primary interface; Git is not required · user brief §4.9
- D-010 · 2026-11-10 · Full state export/import in a human-readable format (e.g. YAML) · backup and disaster recovery, user brief §4.10
- D-011 · 2026-11-10 · Configuration runs through an agent in every guest. VM: installed at first boot via minimal cloud-init. LXC: baked into Plumb-built templates. Proxmox guest agent or SSH only as repair fallback · user brief §4.11
- D-012 · 2026-11-10 · Cloud-init does the minimum (network, bootstrap user, agent) · one configuration path, user brief §4.12
- D-013 · 2026-11-10 · Plumb builds its own images with the same Blocks as normal configuration · Packer replacement, user brief §4.13
- D-014 · 2026-11-10 · An image is a cache, not the source of truth; baked Blocks stay in each target's desired state and are checked for drift · user brief §4.14
- D-015 · 2026-11-10 · Drift becomes an Issue; Plumb never silently overwrites or accepts · user brief §4.15
- D-016 · 2026-11-10 · API-first: plan → approve → apply for every change, risk classes, permission-scoped API tokens, event stream, provenance. MCP and AI help come later on the same API · user brief §4.16
- D-017 · 2026-11-10 · Out of scope for now: Kubernetes/Talos, multi-node clusters, controller HA, controller self-management, non-Debian/Ubuntu guests, mandatory Git workflows · user brief §4.17
- D-018 · 2026-11-10 · Go for controller and agent: one module, two static binaries (`plumb`, `plumb-agent`), `CGO_ENABLED=0` · brief recommendation; single-file deploy, strong concurrency, one language for both sides
- D-019 · 2026-11-10 · Web UI is a Svelte 5 + TypeScript + Vite single-page app, embedded in `plumb`; it uses only `/api/v1`; API types are generated from the OpenAPI file · proves "the UI is a client"; little boilerplate; server-rendered HTML would add a second, non-API surface; user answer Q5
- D-020 · 2026-11-10 · SQLite (WAL, one file) with `modernc.org/sqlite`, plain SQL, forward-only embedded migrations · brief recommendation; trivial backup; pure Go keeps the binary static; no ORM to learn
- D-021 · 2026-11-10 · State is a set of documents (`kind`, `name`, `spec`); a revision is an immutable set of content-addressed documents; the head revision is the desired state · cheap diff, rollback and export from one mechanism
- D-022 · 2026-11-10 · One change flow: proposal → Plan → approve → Revision + Run. A Plan is stale when the head moved. The agent re-observes at apply and refuses a higher risk than approved · no change without a reviewed plan; rollback, import and issue actions reuse the same path
- D-023 · 2026-11-10 · Public API is REST + JSON under `/api/v1`, OpenAPI 3.1 written first, events as SSE, errors as problem+json · standard tools, stdlib only, easy base for MCP later
- D-024 · 2026-11-10 · Agent protocol is HTTPS + JSON; the agent dials out; long poll for commands, POST for reports; own port 8444 with a Plumb CA certificate that agents pin · no open port in guests, stdlib only, every message is an authenticated request; gRPC/WebSocket add dependencies without a need at homelab scale
- D-025 · 2026-11-10 · Enrollment uses a one-time token (bound to one target, single use, 15 min). VM: the token is the SMBIOS serial; `cicustom vendor=` points to one static, root-owned snippet from the installer (CA, URL, install command, no secret); the agent disables cloud-init after enrollment, so `ip`, bootstrap user and `disk` are create-only until a `network` resource and a guest resize exist. LXC: container `env` option, read from `/proc/1/environ`. Then a per-agent bearer credential, stored as a hash · the controller needs no write access to any host directory (no symlink escape, D-006) and no snippet lifecycle; the token never travels over the network before TLS is pinned; a bearer credential is simpler than mTLS with equal protection here
- D-026 · 2026-11-10 · YAML for Blocks and the export; JSON Schema 2020-12 as the only schema language; Go `text/template` for parameter values and file templates · one schema language for validation, UI forms and OpenAPI; all three are standard or stdlib; CUE/HCL/own DSL cost more to learn
- D-027 · 2026-11-10 · The controller renders each target to a flat list of resources (`type:key`); the agent runs observe/diff/apply/watch; listed order inside a Block, Blocks in parallel, one package-manager lock per guest; target `overrides` implement "Accept" and raw mode. Template features beyond plain value templates (`when`, `each`, `uses`, `after`, typed values) wait for a real Block that needs them · few general mechanisms, predictable order, parallel by default, no unused machinery (brief §2)
- D-028 · 2026-11-10 · Drift: same agent in VM and LXC; inotify on parent directories plus a full check every 15 min; the agent ignores events from its own apply; strictness lives in `Diff`; Proxmox level by polling the config digest every 60 s; kernel-level resources are VM-only · immediate for files and packages, complete by the periodic check, no noise from the source
- D-029 · 2026-11-10 · D-005 is implemented as two seams: `Driver` (seven methods, including a pure `Diff` that sets the risk) for Proxmox, and `Resource` for the guest. `driver/proxmox` has its own thin REST client; `driver/fake` is for tests. Proxmox settings of a target are the resource `guest:config` · about 20 endpoints do not justify an SDK; the fake makes the whole flow testable; risk rules for Proxmox changes belong to the driver
- D-030 · 2026-11-10 · Secrets: AES-256-GCM, write-only API, references in documents, masked in diffs/logs/events, export only with a passphrase. The master key file is on its own volume with `backup=0`; the key is created once at install, the installer shows the recovery key once, no passphrase at start; a restore needs the recovery key · user answer Q4; a stolen database, export or LXC backup leaks no secret; stdlib crypto only
- D-031 · 2026-11-10 · Humans: local users, argon2id, strict session cookie, forced password change at first login. API tokens: tiers `read` < `plan` < `apply` (with `max_risk`, at most `disruptive`) < `admin`; only a human session approves `destructive`. The `command` resource is always `destructive`. An `apply` token is root-equivalent on guests; the tiers limit data loss, not privilege · brief §5.9; an AI client can plan but cannot destroy or run arbitrary commands
- D-032 · 2026-11-10 · Proxmox access: user `plumb@pve`, token with privilege separation, role `Plumb`, limited to pool `plumb`, a disk storage, an image storage, the read-only snippet storage, one bridge, node audit. TLS trusts the host CA file or the system roots, not a leaf fingerprint. Minimum Proxmox VE 9.1 · least privilege (D-006); the controller cannot change itself or foreign guests; certificate renewal does not break the link; 9.1 has the LXC `env` option; user answer Q2
- D-033 · 2026-11-10 · Repo layout: `cmd/`, `internal/<package>` (12 packages with a fixed import direction), `api/`, `blocks/`, `web/`, `install/`, `test/` · one obvious place for each thing
- D-034 · 2026-11-10 · Tests: unit with temp root and fake runner; guest tests in Debian/Ubuntu containers; slice tests with `driver/fake` and an in-process agent; recorded Proxmox answers; real-host suite outside CI · the team has no Proxmox host in CI
- D-035 · 2026-11-10 · Conventions: gofmt, go vet, staticcheck, slog, strict TypeScript, eslint, prettier, svelte-check. Go dependency allowlist: `modernc.org/sqlite`, `go.yaml.in/yaml`, `santhosh-tekuri/jsonschema`, `golang.org/x/crypto`, `golang.org/x/sys`; a new dependency needs a decision line · brief §2 "every dependency must justify itself"
- D-036 · 2026-11-10 · Restart mechanism: `service` has `restart_on: [resource ids]`; when a listed resource changes, the agent adds a `restart` change (risk `disruptive`) to the service and applies it after them · one small, visible mechanism instead of general handlers; the Plan shows every restart (review T-002)
- D-037 · 2026-11-10 · An attribute with a secret value is `sensitive`: the agent compares it locally and reports only changed / not changed (no value, no hash), "Accept" is not offered, and the agent stores its desired list with mode 0600 · observed state must not carry secrets into Plans, Issues, events or the database; a hash of a short secret can be brute-forced (reviews T-002, T-016)
- D-038 · 2026-11-10 · Re-enrollment is a Plan: new token, guest restart, risk `disruptive`. An agent that gets a 401 reads the token source again and enrolls again, with backoff · an expired token or a lost credential must not leave a target stuck; no second path besides plan → approve → apply
- D-039 · 2026-11-10 · `plumb serve --dev` uses the fake driver only, plain HTTP and a session cookie without `Secure`; without `--dev` plain HTTP is refused · `browser-shot` and Playwright use a non-localhost HTTP address; dev mode can never touch a real Proxmox host
- D-040 · 2026-11-10 · Plumb is an internal application: the UI and API are for the LAN only, and port 8443 uses a certificate from the Plumb CA. A custom certificate can come later · user answer Q3; no internet-facing hardening or ACME needed now
- D-041 · 2026-11-10 · The Proxmox test host comes later (2026-11-11 at the earliest). T-012, T-013 and the real-host part of T-015 are blocked until `pl-lead` confirms the host; no other card may depend on it · user answer Q1; the slice is built and tested on `driver/fake` first
- D-042 · 2026-11-10 · Web tooling: a `devDependency` that only builds, checks or lints (for example `@sveltejs/vite-plugin-svelte`, `@tsconfig/svelte`, `globals`, `@redocly/openapi-core`) needs no own decision line; every runtime `dependency` of the web app still needs one · the allowlist of D-035 exists to keep shipped code small and reviewed; tools that never reach the user's browser do not need that gate
- D-043 · 2026-11-10 · The JSON Schemas in `internal/state/schema` (documents) and `internal/resource/schema` (resource attributes) are the only source for these shapes. They are closed (`additionalProperties: false`). `api/openapi.yaml` refers to them with `$ref` and does not copy them · one schema source (D-026); a typo in a document is an error in every client
- D-044 · 2026-11-10 · First-slice issue actions are `accept` and `revert` only. `ignore_once` and `ignore_rule` come with the `Rule` kind · the slice API must not offer what the server cannot do (review of T-017)
- D-045 · 2026-11-10 · One vocabulary for the database, the agent protocol and the API. Ids of revisions, Plans, Runs, Issues and comments are integers. States: Plan `pending|approved|stale`; Run `running|succeeded|failed`; step `pending|running|unchanged|applied|failed|refused|skipped`; Issue `open|resolving|resolved` with resolution `accept|revert|gone`. A principal is the string `user:<name>`, `token:<id>`, `agent:<target>` or `system`. An event subject is `<kind>:<id or name>` · two words for one thing need a mapping layer and invite mistakes (brief §2); integer ids are simple and readable ("Plan 12") (review of T-003)
- D-046 · 2026-11-10 · API token tiers are `read` < `plan` < `apply`. Only an `apply` token has a `max_risk` (`reversible` or `disruptive`). `admin` is the tier of a human session; no token has it. This replaces the token part of D-031 · an admin token had no defined approval limit; a tier that only humans have needs no token
- D-047 · 2026-11-10 · One change shape everywhere: `{attr, from, to, risk}` with `from` = guest now and `to` = desired; a sensitive change is `{attr, sensitive, risk}` without values (this replaces the "changed flag" wording of D-037). The controller redacts every agent report with `wire.Redact` before it stores it. The action of a resource is derived by `wire.ActionOf`. An enrollment token is never in a change: `Driver.Update` gets it as `Bootstrap` · the rule is true by type and by one enforced function, not by convention; one meaning of from/to in all layers
- D-048 · 2026-11-10 · A Block use in a Target has an `id` (default: the Block name). Two uses of the same Block need different ids. The id is `wire.Resource.Block` · stable when a Block is inserted or moved; an index would shift
- D-049 · 2026-11-10 · Document hash = SHA-256 of the canonical JSON from `state.Canonical`: members `kind`, `name`, `spec`; keys sorted by byte order at every level; no whitespace; no HTML escaping; numbers as written. A test pins the form · hashes are permanent because revisions share document rows; full RFC 8785 number rules are not needed when number text is kept
- D-050 · 2026-11-10 · `state.Canonical` writes every number in one normal form: the exact value, integers as plain digits (`2048.0`, `2.048e3` → `2048`), other values as a plain decimal without trailing zeros or exponent, `-0` → `0`. A literal longer than 100 characters or with an exponent beyond ±100 is an error. This replaces "numbers as written" in D-049 · a different spelling of the same number must not be a document change (T-003 re-review); nothing was stored before this change
- D-051 · 2026-11-10 · Migration 0002 adds triggers that refuse UPDATE and DELETE on `doc`, `revision` and `revision_doc`, and refuse documents for any revision except the newest. `PRAGMA user_version` counts the applied migrations; a database with a higher number than the program knows is refused · revisions are immutable by the database, not by convention; no extra table for migration bookkeeping
- D-052 · 2026-11-10 · Block value templates run in a sandbox: only `and or not eq ne lt le gt ge len index slice` and `lower upper trim trimPrefix trimSuffix contains hasPrefix hasSuffix replace join default`; no `define`/`template`; `missingkey=error`. Two budgets: one per Target render (default 2 s, 1 MiB output) and one total per `Validate` call over all Targets (default 10 s, 32 MiB output). Each render gets the smaller of its own budget and the rest of the total. When the total is used up, `Validate` stops at once and returns one error that names the total budget (no error per remaining Target). `Load` uses the same budgets. Every `range` body gets a time check and every string function checks its result size · templates are user input; a loop that writes nothing must still stop, and the cost of one save or load must not grow with the number of Targets
- D-053 · 2026-11-10 · `state.Render` returns `guest:config` (type `guest`, empty Block) apart from the agent resources. Overrides replace single attributes, are not templates, must name a rendered resource and cannot change its key attribute. Every rendered resource must match its type schema. `restart_on` must name another agent resource of the same target. A `state.Set` exists only when every document is valid and every Target renders; `state.Load` validates again · errors surface when a document is saved, not at apply time
- D-060 · 2026-11-10 · Agent credential = `<agent id>.<secret>` (secret 256 bit). The store keeps SHA-256 of the secret; `link` compares it in constant time, also against a dummy hash when the id is unknown. A new enrollment token deletes the agent row of its target at once, so the old credential fails before the new agent enrolls. The command queue of a target is bound to its current agent: a new token revokes the in-memory binding and wakes waiting polls, which then get 401; only the agent that enrolled with the new token takes commands or sends reports. Failed credential checks have a per-client rate limit. Unknown, used, expired and replaced tokens get one identical 401 · the id finds the row without a lookup by secret; no oracle tells an attacker which tokens existed
- D-061 · 2026-11-10 · The command queue and the online state live in memory in `link`. A command is delivered once. A `result` or `progress` must name a command that this target received and did not answer (else 409); a `result` that the report handler cannot take (503) stays open for the retry. After a controller restart the agents poll again and T-010 resends what is needed · a durable queue adds a table and a recovery path that the slice does not need; binding results to delivered commands stops cross-target spoofing
- D-062 · 2026-11-10 · `link` redacts every report item before `OnReport` sees it. It uses the union of three sources: the `sensitive` list of the resource in the head revision (`Config.Sensitive`; it survives a restart), the list that `link` last sent to that target in this process (a `watch` replaces the whole list), and the agent's own `sensitive` marks. When neither the head revision nor the sent list knows the resource, `link` removes the values of every change of that item and still accepts the report. When `Config.Sensitive` fails, `link` answers 503 and the agent retries. `Item.Output` is not redacted here; the resource rule of T-005 keeps secrets out of it · the controller decides what is sensitive and the agent can only add to it; redaction must not depend on memory that a restart clears; an unknown resource fails closed and causes no retry loop
- D-063 · 2026-11-10 · `driver.DiffGuest` is the one guest:config diff rule of every driver. Create-only: `kind`, `image`, `disk`, `ip`, `gateway`, `user`, `ssh_keys` (`*CreateOnlyError`). Mutable: `cores`, `memory`, `bridge`, all risk `disruptive`. `driver/fake` uses it and refuses create-only changes in `Update` too · the fake and Proxmox must agree by construction, not by two copies
- D-064 · 2026-11-10 · Plumb CA: ECDSA P-256, 10 years. Listener certificate: 1 year, issued again when it expires within 30 days, when the host names change or when it is not from the CA. TLS 1.3 only. Key files are 0600; a key file that group or others can read stops the start. `GET /agent/v1/binary` (3 per client, then 1 per 20 s) and `POST /agent/v1/enroll` (10 per client, then 1 per 6 s) have a per-IP and a global rate limit; the binary carries `X-Plumb-Sha256` · stdlib only; a changed key mode means someone touched the files
- D-065 · 2026-11-10 · A proposal touches a target when the target is added, removed or renders differently, or when the proposal names it (revert, re-enroll). Only touched targets are observed, and only they must be online. Removing a resource from the desired list stops managing it; it is not deleted on the guest (a Block uses `state: absent` for that) · offline targets must not block unrelated work (T-010); a silent delete on the guest would be a surprise with data loss
- D-066 · 2026-11-10 · A new target plans `guest:config` as `create` (risk `reversible`) and every resource as `create`, `unverified: true`, risk `disruptive`, because nobody can observe a guest that does not exist and the first apply may start services. Deleting a target is `destructive`. The apply of a target gets `max_risk` = the highest risk planned for that target · the Plan shows what is unknown instead of guessing; the approver sees the worst case
- D-067 · 2026-11-10 · A Run has one step for `guest:config` (when it changes) and one per resource of the target's desired list. Step events carry target, resource, status and action, never values. A command whose result does not come back fails its steps after the apply timeout (default 15 min); there is no automatic resend, the user plans again (D-061). After an agent `hello`, the controller sends the `watch` list of the head revision again · a resend could apply twice under a stale approval; a restart of either side must not leave an agent without its desired list
- D-068 · 2026-11-10 · Issue resolution: `revert` is a Plan for the Issue's target with no document change; `accept` puts the Target with the observed values (`from`) as `overrides` of the resource, and is refused for a sensitive change or a change without an observed value. The Issue is `resolving` while its Plan is pending or running, `resolved` (accept/revert, by the approver) when the Run succeeds, and `open` again when the Run fails or the Plan goes stale. An `unchanged` report resolves an open Issue as `gone` by `system`. Guest drift lists create-only differences too, with risk `destructive` (`driver.DriftGuest`) · every resolution is a reviewed Plan (D-022); a failed fix must not hide the drift
- D-069 · 2026-11-10 · Re-enrollment is `Proposal.Reenroll`: it needs an existing guest, not an online agent. The Run makes a new token, calls `Driver.Update` with the sensitive `enroll_token` change and `Bootstrap`, restarts the guest, waits for the new agent and applies the desired list. `link.Config.Sensitive` is backed by the render of the head revision, cached per revision id (D-062) · a target whose token expired before the first boot becomes usable again through the normal flow; one render per head, not per report
- D-075 · 2026-11-10 · An apply changes only what the approved Plan shows. `wire.ApplyBody` carries `planned`: per resource the changes of the Plan, or `unverified` for a resource of a new target. The agent observes again and applies a resource only when every change of the new difference is in its planned changes (`wire.Covers`: same attr, from, to and risk; a sensitive change compares attr and risk only). Any other difference is `refused`: the agent changes nothing of that resource and skips the rest of its Block, the Run fails, and the difference becomes an Issue through the normal drift report. Only `max_risk` limits an `unverified` resource; for all others it stays as a second limit (D-066). A re-enrollment Run applies no resource: the new agent gets the `watch` list, and differences become Issues (this replaces the last step of D-069) · D-015 and D-022: the approver must see every value that an apply overwrites; one risk cap per target let the agent revert drift that no Plan showed
- D-070 · 2026-11-10 · API auth: a session id is 256 random bits, stored as SHA-256, cookie `plumb_session` (`HttpOnly`, `Secure` except `--dev`, `SameSite=Strict`), 12 h. Every non-GET call of a session, and every login, needs `Origin` = `<scheme>://<Host>`. Failed logins are limited to 5 per minute per user and per client (429 + `Retry-After`); an unknown user costs the same argon2id work as a wrong password. A token is `tok_<id>.<secret>` (secret 256 bit, stored as SHA-256, compared in constant time); bad bearers are limited per client. A password change ends the other sessions of the user · stdlib plus `x/crypto/argon2` (D-035); no oracle for user names or token ids
- D-071 · 2026-11-10 · `make build` builds `plumb-agent` first and copies it to `cmd/plumb/agentbin/`, which `plumb` embeds and `link` serves at `/agent/v1/binary`. On a clean checkout the directory holds only `.gitkeep`, the build works and the binary endpoint answers 404. `make check-embed` (in CI) starts the built `plumb serve --dev`, fetches the UI and the agent over the pinned TLS link and compares `version` · one artifact to install; the served agent is always the one of the same build
- D-072 · 2026-11-10 · `plumb serve`: `--dev` means fake driver, plain HTTP, two simulated agents (`link/linktest`) and seeded documents; it refuses `--driver proxmox`. Without `--dev`, plain HTTP and the fake driver are refused, and the API uses a Plumb CA certificate (D-040). Until T-012 a start without `--dev` stops with a clear error. The first start prints the admin password once; `Engine.Recover` runs before the agent listener, the API and the guest poll · D-039 made concrete; no way to point dev mode at a real host
- D-073 · 2026-11-10 · Event types stay the closed enum of `api/openapi.yaml`: step changes are `run.step` (with `status`), agent and enrollment changes are `target.status` (with `agent` or `phase`), resolving, reopened and commented Issues are `issue.updated` (with `status` or `comment`). The contract test validates every emitted event against the `Event` schema. The API adds `DELETE /plans/{id}` (drop a pending Plan: stale, its Issues open again) and `ResourcePlan.unverified` · one vocabulary (D-045); a client can switch on every type
- D-074 · 2026-11-10 · API errors: 409 `plan-stale`, `plan-not-pending`, `issue-not-open`, `target-offline`, `target-busy`, `action-not-allowed`; 422 `validation` with JSON pointers into the request body (`/put/<i>/spec/…`); 403 `forbidden`, `risk-too-high`, `human-required`, `origin-mismatch`, `password-change-required`. Lists are newest first for Plans, Runs and Issues and by name for documents, with an opaque cursor. A document's `revision` is the first revision of the unbroken run up to the head with the same hash · the client can act on the type without parsing text
