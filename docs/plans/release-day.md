## What a stop means

Stop, write down what was seen, and tell the user. Do **not** fix it on the release: no new asset, no edit of an asset, no delete of the draft, and no second workflow run, without the user's word. A draft that is wrong stays a draft until the user decides.

## Never

- **No tag by hand** (`git tag`, `git push --tags`, `gh release create` outside the workflow). The only tag is the one that the user's publish makes.
- **No publish by the workflow or by pl-lead.** The workflow makes a draft only (`--draft`); only the user publishes.
- **No merge of a build input between the tested candidate (`c8d5c15`) and the run without a new RC and a host check** (T-263's R1 points, short form as in R4). Step 3 is the guard: its hashes must equal R4-0.
- No run from a branch, no other version than the user named, no `workflow_dispatch` for a test.
- No secret, token or address in a command line, a log, a PR or the notes (as in every host step).
- No change of a repository setting, secret or branch rule; no force-push; no delete of a run, comment or branch.
