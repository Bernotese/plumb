# Host facts for the slice 7 plan (T-214)

Read-only on `pve-dev`, PVE 9.2.26 (libpve-network-perl 1.6.8, ifupdown2 3.3.0), 2026-11-14. Sources: `/usr/share/perl5/PVE/…` on the node, `pvesh usage`, API GETs with the Plumb token. Nothing changed on the host.

## FACT 1 – notes, `notes-template`, `protected`
- **List returns notes:** `GET /nodes/<n>/storage/<s>/content` returns `notes` (first line only) and `protected` per backup volume (dir: `<file>.notes` and `.protected` files, `Storage/Plugin.pm:1841-1848`; PBS: snapshot `comment`, `PBSPlugin.pm:791`). The list needs `Datastore.Audit` or `Datastore.AllocateSpace` on the storage, and it **silently drops** every volume that fails `check_volume_access`: a backup volume needs `Datastore.AllocateSpace` on the storage **and** `VM.Backup` on `/vms/<owner VMID>` (`Storage.pm:642-644`). With `PlumbGuestBackup` = AllocateSpace + Audit and `VM.Backup` via the pool, Plumb sees the backups of VMIDs that are in the pool now, and nothing else. A backup of a VMID that left the pool is invisible (no error).
- **`notes-template` and `protected` need no extra right.** `POST /vzdump` checks only: root-only `tmpdir dumpdir script job-id`; `Sys.Modify` on `/` for `bwlimit ionice performance`; `Sys.Modify` on `/nodes/<n>` for `stop`; `Datastore.Allocate` for `prune-backups`; `Datastore.AllocateSpace` on the storage (and fleecing storage) (`API2/VZDump.pm:24-34,110-127`, `API2/Backup.pm:39-56`). Both options require `storage`.
- **Template limits:** one line; only `{{cluster}} {{guestname}} {{node}} {{vmid}}`; only `\n` and `\\` escapes (`VZDump.pm:99-118`). `plumb:<install-id>:<target>:<gen>` passes if `<target>` has no `{{`, `\` or newline.
- **A notes failure is only a warning.** vzdump logs "unable to add notes" and the task still ends OK (`VZDump.pm:1225-1235`). So Plumb must read the notes back after the task, and treat a volume without a valid marker as "not Plumb's".
- **Notes are mutable by the token:** `PUT …/content/<volume>` (notes, protected) needs only `check_volume_access` (same AllocateSpace + VM.Backup on owner). The marker is not a proof against an actor who holds the token or root; it protects only against VMID reuse inside Plumb.
- **`protected`:** a protected volume cannot be deleted (`Plugin.pm:1228`). Without `Datastore.Allocate`, `max-protected-backups` defaults to **5 per guest** (`Storage.pm:313-321`); a 6th protected backup fails. Recommendation: Plumb does not set `protected` (retention is Plumb's own delete).
- **Fallbacks** (not needed): `.notes` file through the API = the same `notes` attribute; `GET /nodes/<n>/vzdump/extractconfig` needs `Datastore.Allocate`, or VM.Backup + AllocateSpace (`API2/VZDump.pm:275`). The `notes` attribute is the marker carrier.
- **To prove in the slice 7 acceptance:** a real vzdump with the token and `notes-template`, the list shows the marker; delete of a marked volume with the token.

## FACT 2 – storage config and encryption
- `GET /storage/<id>` needs **`Datastore.Allocate`** (`API2/Storage/Config.pm:180`). Live: the token gets 403 on `plumb-images` (it has Audit there). So the token cannot read it with the D-380 rights.
- But `GET /storage` (index) lists the full config of every storage where the token has `Datastore.Audit` **or** `Datastore.AllocateSpace` (same `api_storage_config`, `Config.pm:121-170`). Live: it lists `plumb-images`, `plumb-snippets`, `local-lvm` with `type`, `content`, `shared`, and more.
- **What tells encryption:** `type` (`pbs` vs `dir`/`nfs`/…) and, for PBS, the key `encryption-key` = the key **fingerprint** (or `1`) when client-side encryption is set; `master-pubkey` = `1` when a master key is set (`PBSPlugin.pm:530,541`). The key itself and the password stay in `/etc/pve/priv/` and are never in the API answer.
- Limits: the field says "configured", not "the key file exists" (vzdump then fails, `PBSPlugin.pm:161`). A dir/NFS on an encrypted disk cannot be seen. Recommendation: read `GET /storage` and filter the storage id; encrypted = `type=pbs` and `encryption-key` set. Keep `--backup-storage-encrypted` only as an override for the dir/NFS case, or drop it.
- **To prove in the slice 7 acceptance:** no PBS on `pve-dev`, so the PBS fields come from the source only.

## FACT 3 – snapshot mode without the guest agent
- **VM:** `mode=snapshot` runs a QEMU backup job (point in time, guest keeps running). fs-freeze happens only if `agent` is enabled in the VM config **and** the agent answers (`VZDump/QemuServer.pm:1094-1117`, `QemuServer/Agent.pm:190-194,309-333`). With no `agent:` line (D-377), the log says "skipping guest filesystem freeze - disabled in VM options" and the backup is **crash-consistent**. UI text: "like a power cut: file systems recover, open app writes may be lost".
- **LXC on `local-lvm` (lvmthin):** snapshot mode works (lvmthin has `snapshot`; else vzdump dies "mode failure", `VZDump/LXC.pm:180-182`). For a running CT, PVE freezes the CT cgroup, syncs its namespace, takes the thin snapshot `vzdump`, thaws, then archives from the snapshot (`LXC/Config.pm:144-148,167-210`; lvmthin needs no extra fsfreeze). Result: file-system consistent, apps crash-consistent. No agent involved. Mount points with `backup=0` are skipped.
- **To prove in the slice 7 acceptance:** one VM and one LXC backup log lines (freeze skipped / snapshot made).

## Part A (D-379) – bridges, tags, `vmbr9`
- Check is `GuestHelpers.pm:424-448` (VM `QemuServer.pm:6265`, LXC `LXC.pm:1727`): zone `localnetwork` unless the name is an SDN vnet (none on `pve-dev`). **With tag T only** `/sdn/zones/localnetwork/<bridge>/<T>` is checked, `SDN.Use`; the bridge path itself is **not** needed. Without a tag: `/sdn/zones/localnetwork/<bridge>`. Trunks: each tag. An ACL on the bridge path with propagate 1 gives every tag.
- **`vmbr9` must be VLAN-aware for a tag.** On a non-VLAN-aware bridge PVE builds `vmbr9v<T>` from the physical ports and dies "no physical interface on bridge 'vmbr9'" when there is none (`Network.pm:673-687`). VLAN-aware path: `bridge vlan add` on the tap, no port needed (`Network.pm:265-290`).
- **How to make it (facts only):** stanza in `/etc/network/interfaces` (not `interfaces.d/`: PVE's parser and `GET /nodes/<n>/network` do not read sourced files, `Network/Interfaces.pm:1059-1062`, so the token would not see the bridge):
  `auto vmbr9` / `iface vmbr9 inet manual` / `bridge-ports none` / `bridge-stp off` / `bridge-fd 0` / `bridge-vlan-aware yes` / `bridge-vids 2-4094`.
  Then `ifreload -a` (ifupdown2). The API way is the same: `POST /nodes/<n>/network` + `PUT /nodes/<n>/network` (= `ifreload -a`, needs `Sys.Modify`, root only for us). Undo: remove the stanza, `ifreload -a`.
- ACLs for the C9 proof: `SDN.Use` on `/sdn/zones/localnetwork/vmbr9/20` (propagate 0) is enough for a NIC with tag 20; an untagged NIC on `vmbr9` needs `/sdn/zones/localnetwork/vmbr9`.
