## Findings for the author (no production edits)

1. `web/src/lib/yaml.ts` `isBlock` / `literal`: leading blank lines followed by an indented first nonempty line can emit invalid YAML. Input `{content: "\n  x\ny"}` emits `content: |-\n\n    x\n  y\n`. YAML infers a four-space block indent, then rejects the two-space `y`. Use explicit block indentation or quote this case.
2. The same literal path does not escape control characters. Input `{content: "a\n\u0000b"}` emits a raw NUL inside the block. YAML rejects it. Single-line strings escape NUL correctly. Quote strings that cannot be literal blocks.

Both findings reproduced with the actual `toYaml` and the already installed dev-only `js-yaml` parser (no added dependency):

```sh
cd web
node --input-type=module <<'JS'
import {toYaml} from './src/lib/yaml.ts';
import {load} from 'js-yaml';
for (const content of ['\n  x\ny', 'a\n\u0000b']) {
  const yaml = toYaml({content});
  console.log(JSON.stringify(yaml));
  try { load(yaml); } catch (e) { console.log(e.reason); }
}
JS
```

Results: `bad indentation of a mapping entry`; `null byte is not allowed in input`. These are display-writer bugs; rollback uses the original JSON documents.
