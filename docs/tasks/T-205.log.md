## Engine tests on the fake command path (card: list them)

The engine itself has no fake `Agents` for commands: `internal/plan` tests use
`link.New` (adopt_test, firewall_off_test, pinrefresh_e2e_test); the API env
uses the real link with `linktest.Agent`. The only fake `Send` is
`auditAgents` in `internal/api/restored_audit_test.go` (wraps the real link to
count calls). Why CI missed F8:

- `internal/plan/adopt_test.go` `TestAdoptFlow` and
  `internal/api/adopt_qa_test.go` `TestAdoptQAApplyTokenRefused` delete an
  adopted Target with **no enrolled agent**, so `unbindGuest` took the offline
  branch and never called `link.Send(unbind)`.
- `linktest.Agent` had no `unbind` case, so no test could have sent it to a
  fake agent either.
- `internal/agent/unbind_test.go` called `a.unbind` directly, not through the link.

Moved to the real path:

- `internal/agent/unbind_link_test.go`: `TestUnbindThroughRealLink` (real link,
  real agent loop, temp root), `TestEveryCommandTypeThroughRealLink` (every
  `wire.AgentCommands()` type through `link.Send`).
- `internal/api/unbind_test.go`: adopt → install-command path enrollment →
  delete through the real link (`TestAdoptedDeleteUnbindsThroughRealLink`),
  the unconfirmed case with warning + park + retry
  (`TestAdoptedDeleteUnbindNotConfirmed`), and `TestForgetAgent`.
- `internal/agent/guest_unbind_test.go` (`-tags guest`, CI guest job, root in
  systemd): `TestGuestUnbind`.

## Known limit

An unbind that succeeded in the guest but whose result reached the controller
after the Run's timeout leaves the park (the agent is gone, never online
again). `agent_left` stays until an admin forgets it; the step text says how
to check by hand.
