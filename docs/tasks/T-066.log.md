## 3. Findings (product defects; evidence kept above)
- **F1 – the build host name reaches every clone's logs.** Seal leaves `/etc/hostname` and `/etc/hosts` with `plumb-build-<image>-v<N>`. A clone's first boot runs under that name until cloud-init sets the Target name, so the journal (both distributions) and on Ubuntu `/var/log/syslog`, `dmesg`, `auth.log` hold it. The C2–C6 criterion fails for clones. Proposal: seal writes a neutral `/etc/hostname` (e.g. `localhost`) and drops the build name from `/etc/hosts`; optionally removes the `/etc/*-` user-database backups that name `plumb-build`.
- **F2 – `/var/lib/systemd/random-seed` is in the template** although the seal step reports "random seed … removed": `systemd-random-seed.service` writes it again at the power-off after seal. Every clone then starts with the same seed file (systemd does not credit it by default, but the step does not do what it says). Proposal: seal stops the service from saving at shutdown (or removes the file in a late shutdown hook), and the template scan of T-066 checks it.
- Minor: a build that the 85 % rule refuses still makes the Image's base template (`image:base` runs first). The Plan object has no "metadata unknown" text; it is only in the Run step output.
