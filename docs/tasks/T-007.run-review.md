## D. Proposed smallest tests (in priority order)

Items 1–3 are one small PR to `run.sh` and `ci.yml` (Codex-sized, about 30 lines). Items 4–6 are guest tests. Item 7 is a new card.

1. **Leftovers and container settings (A3, A6), in `run.sh`.** After `docker run`: `docker inspect -f '{{.HostConfig.CgroupnsMode}} {{len .Mounts}}' "$name"` must print `private 1`, else exit 1. After the loop: `docker ps -aq --filter name=plumb-guest-` and `docker images -q 'plumb-guest-*-'$$` must be empty, else exit 1. Also print the systemd state and, when it is `degraded`, `systemctl --failed --no-legend` (A1).
2. **Forced failure (A4), as a CI step after the green run.** `! bash test/guest/run.sh -test.no-such-flag`. The test binary exits 2 on Debian. Check that the log has no Ubuntu build (`grep -c 'plumb-guest-ubuntu'` = 0), then repeat the leftover check from item 1. No new test code is needed.
3. **Interrupt (A5), as a CI step.** `timeout --preserve-status -s INT 25 bash test/guest/run.sh; test $? -eq 130`. 25 s stops it during the Debian build or the tests. Then repeat the leftover check, and check that no `/tmp/tmp.*/guest.test` is left.
4. **Symlink and hard-link cases as root (B).** Build the existing unit tests into a second binary and run it in the guest: `go test -c -o "$tmp/resource.test" ./internal/resource`, mount it read-only, and run `docker exec "$name" /resource.test -test.run 'Symlink|PathChecks|HardLink|WriteAt'`. This needs no new test code. If a test assumes a non-root user, fix that test. If you keep one mount, put both binaries in one mounted directory instead.
5. **`usermod` with `--` (B).** In `TestFilesAndUser`, after the create: converge the same user with `shell: /bin/sh` and `groups: []`. Then check `getent passwd plumbtest` ends in `:/bin/sh` and `id -nG` has no `adm`. About 8 lines. This also runs the `disruptive` update path on a real guest.
6. **`restart_on` restarts once (B).** In `TestService`, add a drop-in `/run/systemd/system/cron.service.d/count.conf` with `ExecStartPost=/bin/sh -c 'echo x >> /run/plumb-starts'`, `daemon-reload`, truncate the file, apply the doubled restart change, and check that the file has exactly 1 line. Remove the drop-in after the test. About 12 lines.
7. **Agent loop on a real guest (C), new card for pl-codex-qa.** Add `internal/agent/guest_test.go` with build tag `guest`. Reuse the `TestAgentWithRealLink` setup (real link and TLS on loopback), but use `resource.ExecRunner` on `/` and a `state_dir` under `/var/lib/plumb-guest` (root, 0700). Steps: enroll → apply a `file` and a `service` with `planned` → result `applied`, and no drift item for these ids within 2× the debounce → edit the file by hand → one `differs` drift item within the debounce max wait → a `state_dir` with mode 0755 is refused. Run it in the guest like item 4. Add the slow-apply overlap case (M2) later. It needs a slow package and makes CI time unstable.

## Notes
- **N1 – `--privileged` scope.** It is accepted for CI because the runner is ephemeral and has a read-only token without persisted credentials. On the dev VM, a guest test can change the shared host (sysctl, devices, mounts). Rule for new guest tests: no writes under `/proc/sys`, `/sys` or `/dev`, and no `mount`. The reviewer checks this on every change to `test/guest/`.
- **N2 – apt mirror flakiness.** The first attempt failed on an Ubuntu mirror (`resolute-backports`). `Acquire::Retries "5"` is in the image now. If CI goes red on a fetch error again, re-run the job before you call it a regression.
- **N3 – The T-007 card is out of date.** Acceptance criteria 1–3 are still unchecked and the status says "CI pending". Criteria 1 and 3 are proven by this run. Criterion 2 ("fails when a test fails, removes containers in every case") stays open until items 1–3 above are done. pl-lead should update the card and `T-007.run.log.md`.
