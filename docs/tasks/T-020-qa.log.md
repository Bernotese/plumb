## Adversarial checks

Existing tests cover a symlinked parent (Observe and forged Apply, present and absent), dangling target, relative target with `..`, spaces/newline/leading dash, non-empty directory, planned file replacement, absent retaining files/directories, all three drift cases, and convergence.

Added 150 lines (two test files) close gaps: self-link, maximum 4095-byte target, empty directory, Unix socket, actual link-to-file swap between Observe and Apply for present and absent. Non-link inode preservation is asserted. New guest checks cover self/relative/long/special targets, stale plans, and unchanged inode on the second Apply. The existing run.sh resource selector includes both new fake-guest tests, so they also run as root in each distro. No harness or production change is needed.

No failing behavior found in the requested scenarios. Concurrency limitation from code inspection: Apply checks the leaf type before a separate rename/unlink syscall. A concurrent writer can swap a file into the leaf after that check; the later syscall can replace/remove it. The deterministic observe-to-apply swap tests pass; they do not prove safety against a swap during Apply. Report this residual race to review (symlink.go Apply/readLinkAt/symlinkAt). No claim of an atomic compare-and-delete/replace is made by these tests.
