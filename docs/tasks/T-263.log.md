# T-263 – Release re-run on the test host (log)

Owner: pl-backend (the only agent on the host for this card). Reviewer: pl-reviewer (this plan, then the log). **State: RUN PLAN, for review. No host action and no RC on the host until #390, #391 and #393 are merged, pl-reviewer has checked this plan, and pl-lead says go.**

## Rules for this run

- `AGENTS.md` "Test host" in full, and only the steps below. Any other action: ask pl-lead first.
- **Every installer run** (update, remove, clean install, restore, repair) has the same order: `--dry-run` → the result to pl-lead → pl-lead's go → the real run. The `pveum` lines of the dry run are compared with the real run by the ACL view (only the dry run prints `+` lines).
- **Every controller stop** is announced to pl-lead before it.
- **RCs** are built **locally** on the dev VM with `scripts/package-release.sh` from a commit of `main`, in a clean worktree (build output deleted, and the worktree removed without `--force` after it). There is no tag, no GitHub release or draft, and no push of an RC anywhere. For each RC the log records the commit and the four hashes (`plumb`, `plumb-agent`, `install.sh`, the tarball). The RC tarball is copied to the host by `scp` into `/root/plumb-install/t263/`.
- **The release installer is run as the release says:** unpacked as root into a 0700 folder, run from that folder with `--plumb-binary ./plumb`, from a clean root session (`ssh` as root, no `sudo -E`), without any `PLUMB_INSTALL_*` variable and without `TMPDIR`.
- **No new right**, and no change of the network, of `vmbr0`, of the `local`/`local-lvm` definitions or of the SSH setup. `vmbr9` stays (its undo is C8).
- **Copies at the start:** `storage.cfg` and the ACL view (rows, normalized). At the end: `storage.cfg` byte-equal, the ACL view equal.
- **Real `plumb key init` runs** are allowed (D-180). The recovery key goes to `~/.config/plump/testhost-recovery.key` (0600); the log says only "key stored in <path>". A TTY comes from `ssh -tt`; a key or token is passed only by a 0600 file or stdin, never on a command line.
- **The log holds** no address, token id, MAC, key, fingerprint or host local time: times in UTC (`…Z`), and volumes by VMID and UTC time, not by their file names.
- **Test objects** live only in the Plumb pool and are named `t263-*`. The cleanup comes at the end, with pl-lead's go; the test secret files go after it (D-416).
