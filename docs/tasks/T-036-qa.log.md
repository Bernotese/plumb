## Findings (no production fixes)

- **F1 — P2: enum takes precedence over writeOnly.** `web/src/lib/schemaForm.ts`, `kindOf`, checks string enum before writeOnly. Reproduce with `fieldsOf({properties:{password:{type:"string",writeOnly:true,enum:["literal-example"],default:"literal-example"}}})`: kind is `enum`, initial form value is `literal-example`, and `toParams` saves the literal. Expected: secret picker, empty initial selection, reference-only request. This is new T-036 secret support failing for a supported schema combination; backend rejection does not prevent the UI from sending the literal.
- **F2 — P2: mock approves human-only Plans for tokens.** `web/src/lib/mock/mock.ts`, `approvePlan`, checks authentication/status but not `human_only`. Reproduce: `api=createMockApi({token:true,stepDelayMs:0})`; `p=await api.resolveIssue(8,"ignore_rule")`; `p.human_only` is `["rule-change"]`; `await api.approvePlan(p.id)` succeeds and commits a revision. Expected: 403 human-required. The Plan screen states that an API token cannot approve. This finding is limited to the mock; production enforcement is outside this audit.

Both expected-behavior probes failed as described (`/tmp/t036-probes.log`). The temporary probe test was removed. Passing screen coverage injects a 403 only to check error rendering; it does not claim the mock enforces approval authorization.
