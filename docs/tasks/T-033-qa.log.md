## Findings

1. **QA-033-1 — high: a refused import can change secrets (409 and 422).**
   `internal/plan/import.go` calls `WriteSecrets` before `Propose` checks
   create-only guest changes and offline/busy targets. `writeBundle` creates
   secrets, replaces explicitly allowed values, emits events, and stales Plans.
   A later error does not roll back those writes. Comparing SQLite content
   before and after proved:
   - changing an existing target's disk from 10 to 40 returns 422 `validation`,
     yet creates `new` and replaces the live `app-db` value;
   - changing cores with the target offline returns 409 `target-offline`,
     yet creates `new` and emits `secret.updated`.
   No import Plan is returned in either case. This fails the requested
   no-write-on-409/422 property. D-153 explicitly allows secret writes to stay
   when planning fails, so this is also a decision conflict for the lead.
   It is not an unapproved overwrite: the 422 probe explicitly lists `app-db`
   in `overwrite`. Without that list, 409 `secret-conflict` is atomic and passes.

2. **QA-033-2 — medium: anchors on mapping keys bypass rejection (D-151).**
   `internal/state/export.go:fromNode` checks the current node for anchors,
   but handles mapping keys without calling `fromNode` on them. This input
   returns 201 and creates a Plan instead of 422:
   ```yaml
   &a kind: Export
   format: 1
   secrets: []
   ```
   Value anchors and alias bombs are rejected. This does not demonstrate
   alias expansion; it demonstrates that the promised no-anchor format is
   not enforced on every node.

## Added coverage

`internal/api/export_qa_test.go` adds a read-only logical SQLite snapshot
helper (all table rows, sorted, including ciphertext/counters/events), hostile
API probes, slot exhaustion, actual key-material scans, approval boundary,
and exact round trip. `export_test.go` applies snapshots to all existing
refusal cases and the live-store conflict. `env_test.go` retains the generated
key for the scan. The test diff exceeds the ~150-line aim because the shared
snapshot helper checks all database tables instead of only secret metadata.

A successful plain import creates a pending Plan and its audit event before
approval. It does not change documents, revisions, bindings, runs, secrets or
identity tables. D-095/D-153 explicitly allow bundle secret writes before
approval; therefore literal “no DB writes before approval” is not a product
invariant. The added boundary test checks the state tables rather than the
expected Plan/event writes.

User/Token/Session documents return 422 with no DB writes. GET export reads
no identity tables. Header-only ignored extension fields cannot create users,
tokens or sessions because only validated state documents enter the proposal.

then run `go test ./internal/api -run TestQAProbe -v -count=1`.

package api

import (
	"github.com/Bernotese/plumb/internal/link"
	"github.com/Bernotese/plumb/internal/plan"
	"path/filepath"
	"strings"
	"testing"
)

func TestQAProbeLate422(t *testing.T) {
	src, adm := exportEnv(t, "replacement-canary")
	adm.do("PUT", "/api/v1/secrets/new", map[string]string{"value": "new-canary"})
	_, _, file := src.export(adm, exportPass)
	file = strings.Replace(file, "disk: 10", "disk: 40", 1)
	dst, dadm := exportEnv(t, "live-canary")
	before := qaImportDB(t, dst, "secret", "secret_counter", "plan", "event")
	code, body := dst.importFile(dadm, map[string]any{"content": file, "passphrase": exportPass, "overwrite": []string{"app-db"}})
	t.Logf("status=%d response=%s DB_changed=%t", code, body, before != qaImportDB(t, dst, "secret", "secret_counter", "plan", "event"))
	vals, err := dst.sec.Resolve(dst.ctx, []string{"app-db", "new"})
	if err != nil {
		t.Fatal(err)
	}
	t.Logf("live_overwritten=%t new_created=%t", vals["app-db"].Text == "replacement-canary", vals["new"].Version > 0)
	if code == 422 && before != qaImportDB(t, dst, "secret", "secret_counter", "plan", "event") {
		t.Fatal("422 import wrote secrets and events")
	}
}
func TestQAProbeAnchorKey(t *testing.T) {
	e := newEnv(t, true)
	adm := e.admin()
	code, body := e.importFile(adm, map[string]any{"content": "&a kind: Export\nformat: 1\nsecrets: []\n"})
	if code != 422 {
		t.Fatalf("anchored mapping key accepted: %d %s", code, body)
	}
}
