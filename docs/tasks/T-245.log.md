**Findings (for a fix card; the tests pin what holds today):**
- **F1 (low/medium):** an Issue whose `GET /issues/{id}` answer is over 256 KiB (the MCP client's read cap, `MaxResult`) makes `explain_issue` fail as a whole: "the answer of /api/v1/issues/1 is longer than 262144 bytes". A drift of a big file (about 200 000 multi-byte runes in the value) is enough. Expected by §21: a prompt with the value cut. Fix idea: read the Issue with a higher cap for this one call, or ask the API for the Issue without the full values and cut them on the server side.
- **F2 (low):** the comments before the last 20 are dropped without a mark (`lastComments`), so the client does not know that older comments exist. §21 says "caps are visible". Fix: `"left_out": N` (or `"older_comments": N`) when more than 20.
