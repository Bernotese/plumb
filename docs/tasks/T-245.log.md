**Findings (for a fix card; the tests pin what holds today):**
- **F1 (low/medium):** an Issue whose `GET /issues/{id}` answer is over 256 KiB (the MCP client's read cap, `MaxResult`) makes `explain_issue` fail as a whole: "the answer of /api/v1/issues/1 is longer than 262144 bytes". A drift of a big file (about 200 000 multi-byte runes in the value) is enough. Expected by §21: a prompt with the value cut. Fix idea: read the Issue with a higher cap for this one call, or ask the API for the Issue without the full values and cut them on the server side.
- **F2 (low):** the comments before the last 20 are dropped without a mark (`lastComments`), so the client does not know that older comments exist. §21 says "caps are visible". Fix: `"left_out": N` (or `"older_comments": N`) when more than 20.

## C2: data disks (T-238, #373), by pl-reviewer (not its author)

**What:** `internal/api/disks_qa_test.go`, through the API env and the fake driver. The fake now keeps a detached volume as an `unused` entry, as Proxmox does (T-244 D7, D8): after a failed free, and for a foreign volume that a Plan detaches. `FreeVolume` models a person's free.

Not repeated here (the author's tests cover them): the D-437 undo (`TestCTDisksThroughTheAPI`, the driver tests), the restore note (`TestRestorePlanNamesMissingDisks`), `disks-not-adoptable` (so an unbind of an adopted Target never has disks).

**Mutants** (each after a commit, undone with `git checkout`):
| Mutant | Caught by |
|---|---|
| a remove is `reversible` | ApprovalByTier, MissingThenEmpty, Occupied |
| an add while `guest:volume-left` is open | VolumeLeftLifecycle |

**Findings (for a fix card; the tests pin what holds today):**
- **F1 (medium):** `POST /issues/{id}/resolve` with `ignore_rule` is accepted for `guest:volume-left` (only `guest:restore-failed` is refused, `internal/issue/issue.go` near line 345). A plan token makes a Rule Plan (201; approving it is a human `rule-change`, and the Rule would do nothing, `ignore.go`). But the Issue becomes `resolving`, and the Intake ends only an `open` Issue, so the poll's "the volume is gone" report is dropped: the Issue does not end when a person frees the volume, until that Plan is dropped. Fix: refuse `ignore_rule` for `guest:volume-left` as for `guest:restore-failed`, and leave it out of `actions`; a test.
- **F2 (medium, host fact for T-247):** the way out says `pvesm free <volid>`. The poll checks the guest **config** (`unusedN` lines), and only when the config digest changes. If `pvesm free` of a volume that an `unusedN` line still names leaves that line, or is refused, the Issue never ends. T-247: check on `pve-dev` what `pvesm free` does with such a volume. The way out is probably `qm set <id> --delete unusedN` / `pct set <id> --delete unusedN` (it frees the volume and changes the config); else the check must read the storage list.
- **F3 (low, fixed here):** the fake removed a detached volume without a trace. Proxmox keeps it as `unusedN`. With the old fake the poll ended `guest:volume-left` at once, so a test of its life could not fail.

**Findings:**
- **H1 (high, sent to #374 before its merge):** `restoreFailedOpen` counts **every** open `guest:restore-failed` as "the last restore failed", also the D-439 "restored, the re-enroll was refused" state. A restore of that Target then takes **no safety backup** of the good restored guest (D-420 allows that only for a broken guest), writes no "running" Issue, and on a failure keeps the old "restored" text **and the old Run id**. So `restoredProof` still passes, and the gate lets a re-enroll of a guest that may have no disk through. Fix: only the "running" and "failed" states count as broken (also for `checkBroken`). `TestQARestoreProofEndsWithALaterRestore` pins the fix.
- L2 of my #374 review stays a later card: a stop between the revoke and the restore call says "may have no disk" at the next start, although no disk was touched.

**Runs:** `go test ./internal/api -run TestQARestore` (7 tests; all pass on `main` with the H1 fix of #374). Proving CI job: `lint, test, build`. Nothing skips locally.
