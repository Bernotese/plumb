## Ubuntu 26.04 diagnosis (pl-lead go: (a) ARP on tap9001i0 only, then (c) read-only SSH)
- (a) ARP-only capture on `tap9001i0`, 120 s + 90 s: no ARP frame at all (the guest's ARP cache was warm; the tap carried traffic: RX/TX counters grew). The guest's real address came from the neighbor table of the controller LXC (`pct exec 100 -- ip neigh`, read-only): one REACHABLE entry for the VM's MAC, an address in the LAN that is **not** PLUMB_TEST_VM_IP_2.
- (c) SSH as `plumb` with the guest test key to that address (host as jump), read-only (addresses and MACs redacted):
  - `ubuntu 26.04`; `cloud-init status`: disabled by the Plumb agent's marker (after enrollment, D-025); datasource NoCloud `/dev/sr0`.
  - `ip -br addr`: the NIC is **`ens18`** with a **DHCP** address; `ip route`: `default … proto dhcp`.
  - `/etc/netplan/50-cloud-init.yaml` (from Proxmox's network data v1): `eth0: match: macaddress …, set-name: eth0, addresses: [<VM_IP_2>/24], routes: default via <VM_GW>` – the wanted static config.
  - `cloud-init.log`, init-local: `Failed to rename devices: Failed to apply network config names: [busy] Error renaming mac=<mac> from ens18 to eth0`, then netplan rendered.
  - `/run/systemd/network/10-netplan-eth0.network`: `[Match] PermanentMACAddress=<mac>` **and** `Name=eth0` → never matches `ens18`. `networkctl status ens18`: Network File `/run/systemd/network/zzzz-dracut-default.network` (`DHCP=yes` for every NIC), package `dracut-network` installed.
- Cause: Ubuntu 26.04's dracut initramfs brings the NIC up with DHCP before cloud-init's init-local; the NIC is "busy", so the rename `ens18 → eth0` fails; netplan's networkd file matches the MAC **and** the name `eth0`, so it does not apply, and the dracut DHCP default stays. Proxmox (qemu-server `Cloudinit.pm`) always names the NIC `eth0` in the network data. Debian 13 is fine because its cloud image boots with classic names: the NIC is already `eth0` (seen in the T-012 guest), no rename is needed.
- Where the fix is: not in the Target settings (address, gateway, user are right) and not in the network data format/version of the driver (Plumb does not write it; Proxmox does, with a fixed `eth0`). It is the Ubuntu 26.04 image together with Proxmox's fixed name. Proposals for pl-architect: (1) Image level: an Ubuntu template whose initramfs does not configure the network (or boots with `net.ifnames=0`), as part of the image build (T-039); (2) vendor snippet workaround for all guests (a `bootcmd` that renames the MAC-matched NIC to the network-data name and runs `netplan apply`); fragile, it changes every guest; (3) Proxmox upstream: network data that matches by MAC without a fixed name. Until then T-015 can run Ubuntu with DHCP + the agent-reported address, or accept "Ubuntu 26.04 stock image: static address not supported" as a known limit.
