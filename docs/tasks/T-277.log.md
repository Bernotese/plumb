## c1: the proxy (design; the script lives only in my scratchpad, not in the repo)

- **Tunnel:** `ssh -N -L 127.0.0.1:<t>:$IP:8443 "$PLUMB_TEST_PVE_SSH"`, started in the background. Its PID is noted, and it is stopped by that PID (never `pkill -f`).
- **Proxy:** `python3` (stdlib only: `http.server.ThreadingHTTPServer` + `http.client.HTTPSConnection`), about 80 lines.
  - **Listen:** only on the dev VM address that `mobtest` reaches, on a free port `<p>`, and only for the minutes of c1.
  - **Peers (P1):** a connection is served only when its peer address (`client_address`) is `mobtest`'s address. Every other peer gets 403 before anything is forwarded, and is counted.
  - **TLS to the controller:** an `ssl` context with the Plumb CA file (`pct pull 100 /var/lib/plumb/link/ca.crt`, a 0600 copy) and `check_hostname` on, with `server_hostname=$IP` (the certificate's name), over the tunnel socket to `127.0.0.1:<t>`. No `--insecure` between the proxy and the controller.
  - **Session:** at start, the proxy reads `t277-view`'s password from a 0600 file and logs in with `POST /api/v1/session`. It keeps the session cookie only in memory and adds it to every request it forwards. It drops any `Cookie` and `Authorization` header that the browser sends, and drops `Set-Cookie` from the answers.
  - **Read only:** `GET` and `HEAD` are forwarded; every other method gets 405 and is counted.
  - **Paths let through (P1), nothing else (404, counted):**
    - `/` and `/index.html` (the single page app);
    - `/assets/<name>.js` and `/assets/<name>.css` (a name of letters, digits, `.`, `_`, `-`), the built UI files;
    - `GET`/`HEAD` under `/api/v1/` (what the screens read, `GET /api/v1/session` included), except `/api/v1/export` and every path under it. A read session may export the whole desired state, and no picture needs it: refused with 403 and counted. `GET /api/v1/events` (SSE) is streamed in chunks with a flush.
  - **Log:** per request only the method, the path without the query, and the status; never a header or a body.
- **The user:** `t277-view` (role `read`) is made by the admin before c1. Its one-time password and the first-login change go by a 0600 file and stdin; the new password goes into `t277-secrets.json`.
- **The end, in this order (P2, P3):**
  1. the pictures of the screens are done;
  2. `DELETE /api/v1/session` by the proxy's own client: the cookie is dead;
  3. the picture of the login page, through the same proxy (now without a live session; no second listener);
  4. `t277-view` disabled (admin);
  5. the proxy stopped by its PID;
  6. the tunnel stopped by its PID (never `pkill -f`);
  7. the 0600 files (the CA copy, the password file) deleted.
- **If the proxy way fails for a technical reason:** only the login page is taken, and the log says so. A change of the shot tool in `mobtest` then becomes a question for the user (through pl-lead). The other screens stay proven by tests only.
